# 内容存储设计

文档内容使用 PostgreSQL 持久化，不使用 OSS，也不依赖仓库中的运行时文档文件。

## 数据关系

- `docs_state`：站点名称、工作区修订号和当前发布指针。
- `docs_node_identities`：节点稳定身份和删除 tombstone。
- `docs_document_versions`：不可变的 Markdown、OpenAPI 或分组正文版本。
- `docs_drafts`：当前草稿树中的父子关系、排序和版本引用。
- `docs_releases`：发布记录。
- `docs_release_nodes`：某次发布对应的不可变目录快照。
- `docs_audit`：保存、发布和操作者元数据。
- `docs_draft_changes`：按修订记录草稿增量。

内容正文和目录结构分离保存：移动节点只改变位置，不复制正文；相同正文版本可以被多个发布快照复用。删除节点保留身份记录，避免历史快照失去引用。

## 发布流程

1. 管理员编辑草稿并保存。
2. 服务端在事务中校验树结构并记录修订。
3. 发布时复制节点引用形成 release 快照。
4. 事务提交后更新当前发布指针。
5. 浏览端和公开 MCP 只读取当前发布快照。

因此，编辑不会污染用户正在阅读的版本；每次发布可通过 release ID 定位，历史快照可按需保留或清理。
